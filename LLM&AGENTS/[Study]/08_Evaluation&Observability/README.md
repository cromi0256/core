# 평가
![Image](https://www.anthropic.com/_next/image?url=https%3A%2F%2Fwww-cdn.anthropic.com%2Fimages%2F4zrzovbb%2Fwebsite%2F0205b36f9639fc27f2f6566f73cb56b06f59d555-4584x2580.png&w=3840&q=75)

LLM 평가는 모델이나 AI 시스템이 정의된 일련의 기준에 따라 얼마나 잘 작동하는지 측정하는 체계적인 테스트이다.

출력 결과를 비공식적으로 판단하는 대신, 프롬프트 버전, 모델 업데이트, 시스템 변경 사항을 비교하는 재현 가능하고 정량적인 방법을 제공한다.

주요 프레임워크 : [DeepEval](https://deepeval.com/docs/introduction), [RAGAS](https://docs.ragas.io/en/stable/)

1. 결정론적 평가 : 고정된 규칙 기반의 검증을 통해 모델의 출력 결과를 평가
  - 응답에 필수 키워드가 포함되어 있는지, 예상된 형식과 일치하는지, 또는 알려진 정답과 정확히 일치하는지 등을 확인
  - 빠르고 비용이 적게 들며 완전히 재현 가능하기 때문에, 어떤 시스템에나 적합한 첫 번째 평가 단계

2. 모델 기반 평가 : AI 모델을 사용하여 LLM 애플리케이션의 출력을 자동으로 채점하거나 평가
   - 평가 기준을 설명하는 프롬프트를 작성하면, 심사 모델이 응답을 평가
   - 주관적이고 개방적인 품질 요소를 처리할 수 있으며, 인간 검토보다 훨씬 저렴한 비용으로 확장가능

3. 인간 평가 : 사람이 정의된 기준에 따라 모델의 출력을 직접 검토하고 점수를 매기는 과정
   - 미묘하거나 주관적인 품질 측면을 평가하는 데 있어 가장 정확한 방식이며, 다른 평가 방법의 유효성을 검증하는 기준이 됨
   - 중요한 의사 결정을 내리거나, 자동화된 평가를 보정하거나, 다른 방법에서 식별된 경계 사례를 검토하는 데 사용

4. 평가 지표 : 품질 기준에 따라 LLM의 출력을 점수화하기 위해 사용되는 구체적인 측정 항목
   - 응답이 사실에 근거했는지, 질문과 관련이 있는지, 유해한 내용이 포함되지 않았는지, 사용자에게 진정으로 유용한지 등 품질의 서로 다른 측면을 평가
   - 지표는 시스템이 무엇을 최적화할지, 그리고 실제로 어떤 오류 유형을 감지할 수 있는지를 결정하기 때문에 핵심적

# 관측가능성
LLM 관측 가능성(LLM observability)이란, AI 애플리케이션 내부에서 일어나는 과정을 모니터링하고 파악하는 관행이다.

오류 디버깅이나 출력 결과가 변경된 원인을 파악하여, 개발 및 운영 환경에서 시스템의 동작에 대한 지속적인 기록을 확보할 수 있다.

주요 프레임워크 : LangSmith, LangFuse, Helicone, Arize AI

1. 추적과 로깅 : 특정 상호작용 과정에서 정확히 어떤 일이 발생했는지 재구성
   - 추적 : 초기 사용자 입력부터 중간 단계의 LLM 호출, 도구 사용, 검색 단계 등을 거쳐 최종 응답에 이르기까지 AI 시스템을 통과하는 요청의 전체 라이프사이클을 기록
   - 로깅 : 오류, 지연 시간 급증, 예상치 못한 출력 등과 같은 개별 이벤트를 포착
  
2. 비용 및 지연 시간 모니터링
   - 토큰당 요금이 상당히 높은 대규모 추론 모델을 사용할 때 운영 비용이 눈에 띄지 않게 빠르게 누적 될 수 있음
   - 간단한 쿼리를 비용이 저렴한 모델로 라우팅하거나 자주 나오는 응답을 캐싱하여 중복된 API 호출을 줄임

3. 운영 모니터링 : AI 시스템이 실제 서비스에 투입되어 실제 사용자 트래픽을 처리하기 시작한 후 이를 지속적으로 관찰
   - 실제 운영 단계에는 극단적인 사례, 예상치 못한 입력값, 오류 발생 양상이 드러남
   - 품질 지표, 오류율, 시간 경과에 따른 동작 변화를 추적하여, 회귀 현상이나 이상 현상이 다수의 사용자에게 영향을 미치기 전에 이를 포착
